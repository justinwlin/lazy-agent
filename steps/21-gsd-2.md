# Step 21: GSD 2 - Autonomous Coding Agent

GSD 2 is the evolution of Get Shit Done — now a standalone CLI and real coding agent built on the Pi SDK. Unlike GSD v1 (prompt framework), GSD 2 has direct control over context windows, sessions, git branches, cost tracking, and execution.

**Time estimate: ~2 minutes**
**Type: OPTIONAL** - For users who want fully autonomous project execution

---

## Why This Matters

GSD v1 was a prompt framework — it asked the LLM to do things and hoped it followed instructions. GSD 2 is a TypeScript application that *controls* the agent session:

| Feature | v1 (Prompts) | v2 (Agent) |
|---------|-------------|------------|
| Context management | Hope LLM doesn't fill up | Fresh session per task |
| Auto mode | LLM self-loop | State machine on disk |
| Crash recovery | None | Lock files + session forensics |
| Git strategy | LLM runs git commands | Worktree isolation, squash merge |
| Cost tracking | None | Per-unit token/cost ledger |
| Stuck detection | None | Retry once, then diagnostics |
| Parallel execution | None | Multi-worker orchestration |
| Verification | Manual | Automated with auto-fix retries |

One command. Walk away. Come back to a built project with clean git history.

## Step 4: How to Use GSD 2

### Step Mode (Interactive)

```bash
cd your-project
gsd
```

GSD reads the project state and walks you through the next step. It pauses between units so you can review.

### Auto Mode (Autonomous)

```bash
gsd auto
```

This is the main event. GSD 2:

1. **Fresh session per task** — Every task gets a clean 200k-token context window
2. **Context pre-loading** — Dispatch prompt includes inlined plans, summaries, and decisions
3. **Git worktree isolation** — Each milestone runs in its own worktree branch
4. **Crash recovery** — Lock files track state; resume from where you left off
5. **Stuck detection** — Retries once with diagnostics, then stops
6. **Cost tracking** — Per-unit token/cost captured with projections
7. **Adaptive replanning** — Roadmap reassessed after each slice

Press **Escape** to pause auto mode anytime.

### Quick Mode

```bash
gsd quick
```

For ad-hoc tasks that don't need full milestone planning.

### Other Useful Commands

```bash
gsd status              # Show current project state
gsd doctor              # Diagnose issues
gsd cost                # Show cost breakdown
gsd next                # Run next step
gsd migrate             # Migrate from GSD v1 (.planning → .gsd)
```

## Work Structure

GSD 2 organizes work into a hierarchy:

```
Milestone  →  a shippable version (4-10 slices)
  Slice    →  one demoable vertical capability (1-7 tasks)
    Task   →  one context-window-sized unit of work
```

The iron rule: **a task must fit in one context window.** If it can't, it's two tasks.

State is stored in `.gsd/` directory (not `.planning/` like v1).

---

## Key Differences from GSD v1

- **v1** installs slash commands into Claude Code (`/gsd:new-project`)
- **v2** is a standalone CLI (`gsd auto`)
- **v1** uses `.planning/` directory
- **v2** uses `.gsd/` directory
- **v1** relies on LLM following prompts
- **v2** has programmatic control over sessions

You can use both — v1 for quick slash commands, v2 for autonomous execution.

---

## Migrating from v1

If you have existing `.planning` directories:

```bash
gsd migrate
```

This converts `.planning` → `.gsd` format, preserving completion state.

## Troubleshooting

### `gsd` command not found?

Make sure the npm global bin is in your PATH:

```bash
export PATH="$(npm config get prefix)/bin:$PATH"
```

Add to `~/.zshrc` to persist.

### Node version issues?

GSD 2 works best with Node.js LTS. Check with:

```bash
node --version
```

### Want to see what's happening?

```bash
gsd status
gsd doctor
```
